# Overview

This repository documents my investigation process while completing the **Oski** challenge on CyberDefenders.

Instead of publishing challenge answers, this write-up focuses on **how I investigated a suspicious malware sample using multiple threat intelligence platforms**, how I correlated findings across different sources, and the techniques I learned throughout the investigation.

The challenge demonstrates a realistic Threat Intelligence workflow where a SOC analyst starts with a suspicious file hash and gradually uncovers malware behavior, command-and-control infrastructure, attacker techniques, and Indicators of Compromise (IOCs).

---

# Scenario

A company accountant received an email containing a PowerPoint attachment disguised as a legitimate invoice.

Shortly after opening the attachment, the organization's SIEM generated an alert indicating that a potentially malicious file had been downloaded.

My objective was to investigate the suspicious file using public threat intelligence platforms to understand its behavior, identify attacker infrastructure, and document its capabilities.

# Investigation Walkthrough

---

## Objective 1 – Examine the Malware Sample

### My Approach

I began by searching the provided file hash on VirusTotal.

Before investigating the malware itself, I reviewed the sample metadata to understand when the file first appeared, how widely it was detected, and whether the security community had already analyzed it.

### Why I Looked There

VirusTotal provides an excellent starting point for malware investigations because it aggregates antivirus detections, metadata, behavioral reports, and community intelligence.

### Skills Practiced

* Malware Triage
* Threat Intelligence
* File Reputation Analysis

### What I Learned

Metadata helps establish context before deeper malware analysis begins.

---

## Objective 2 – Investigate Command & Control Activity

### My Approach

After reviewing the sample details, I examined the network relationships associated with the malware.

Rather than focusing solely on detection results, I reviewed contacted URLs and external infrastructure to understand how the malware communicated after execution.

### Why I Looked There

Identifying attacker-controlled infrastructure allows defenders to create detection rules and block malicious communication.

### Skills Practiced

* IOC Collection
* Network Threat Intelligence
* Infrastructure Analysis

### What I Learned

Command-and-control infrastructure often provides the strongest indicators for threat hunting.

---

## Objective 3 – Review Malware Behaviour

### My Approach

Next, I explored the dynamic behaviour report generated by VirusTotal.

I reviewed the HTTP requests, downloaded resources, and execution sequence to understand what actions occurred immediately after infection.

### Why I Looked There

Behaviour reports explain how malware operates once executed rather than simply identifying that it is malicious.

### Skills Practiced

* Dynamic Malware Analysis
* Behaviour Analysis
* Threat Investigation

### What I Learned

Runtime behaviour provides valuable context that static analysis alone cannot reveal.

---

## Objective 4 – Investigate Malware Configuration

### My Approach

To enrich the investigation, I pivoted to Recorded Future Tria.ge using the same malware hash.

I reviewed the malware configuration section to identify embedded configuration values, encrypted strings, and other indicators extracted during sandbox analysis.

### Why I Looked There

Different intelligence platforms often expose unique artifacts that are unavailable elsewhere.

### Skills Practiced

* Threat Intelligence Correlation
* Malware Configuration Analysis
* Sandbox Investigation

### What I Learned

Cross-platform analysis significantly improves investigation quality.

---

## Objective 5 – Map MITRE ATT&CK Techniques

### My Approach

After understanding the malware's execution, I analyzed its mapped MITRE ATT&CK techniques using ANY.RUN.

Rather than memorizing ATT&CK IDs, I focused on understanding why each observed behaviour aligned with a specific attacker tactic.

### Why I Looked There

MITRE ATT&CK provides a standardized language for describing adversary behaviour.

### Skills Practiced

* MITRE ATT&CK Analysis
* Threat Modeling
* Adversary Behaviour Analysis

### What I Learned

Mapping behaviour to ATT&CK techniques makes malware investigations much easier to communicate.

---

## Objective 6 – Review Defense Evasion Behaviour

### My Approach

I continued reviewing the sandbox report to identify any defense evasion activity performed after execution.

I focused on actions related to cleanup, artifact removal, and techniques commonly used to reduce forensic evidence.

### Why I Looked There

Understanding defense evasion techniques helps defenders improve detection coverage.

### Skills Practiced

* Defense Evasion Analysis
* Malware Behaviour Investigation
* Threat Hunting

### What I Learned

Many malware families attempt to remove traces of execution after completing their objectives.

---

## Objective 7 – Correlate Multiple Intelligence Sources

### My Approach

Throughout the investigation, I continuously compared findings across VirusTotal, Tria.ge, and ANY.RUN.

Instead of trusting one platform exclusively, I validated observations using multiple independent intelligence sources.

### Why I Looked There

Threat Intelligence becomes more reliable when multiple trusted platforms report the same behaviour.

### Skills Practiced

* IOC Validation
* Intelligence Correlation
* OSINT Investigation

### What I Learned

Correlating intelligence across platforms greatly increases confidence in investigation findings.

# Defensive Recommendations

* Block known malicious domains and IP addresses identified during threat intelligence investigations.
* Enrich SIEM alerts using external threat intelligence feeds.
* Monitor suspicious PowerShell and script execution activity.
* Detect unexpected outbound HTTP requests initiated by Office applications.
* Deploy EDR rules for known malware behaviours rather than relying solely on signatures.
* Regularly validate Indicators of Compromise against multiple intelligence sources.
* Incorporate MITRE ATT&CK mapping into SOC detection engineering.

---

# Key Takeaways

* Threat intelligence investigations often require pivoting across multiple analysis platforms.
* VirusTotal provides an excellent starting point but should not be the only intelligence source.
* Behaviour analysis reveals significantly more than antivirus detections alone.
* Intelligence correlation increases confidence and reduces false assumptions.
* MITRE ATT&CK provides valuable context for understanding attacker objectives and techniques.

---

# Reflection

This lab strengthened my understanding of **Cyber Threat Intelligence** by demonstrating how multiple public intelligence platforms can be combined to investigate suspicious malware.

Rather than relying on a single source, I learned how to pivot between **VirusTotal**, **Recorded Future Tria.ge**, and **ANY.RUN** to collect Indicators of Compromise, analyze malware behavior, investigate command-and-control infrastructure, and validate findings through correlation.

The challenge also reinforced the importance of mapping malware activity to the **MITRE ATT&CK Framework**, helping translate technical observations into standardized attacker behaviors that can be applied during SOC investigations and threat hunting.

The biggest lesson from this lab was that effective threat intelligence is built through **correlation, validation, and context**, not by depending on a single analysis platform.
